# Архитектура системы бесконтактного взвешивания КРС

Цель: оценка живой массы взрослой коровы (450–700 кг) по фото/видео со смартфона
с погрешностью **не более ±10 кг (~1.5–2%)**.

---

## 1. Методология и обоснование точности ±10 кг

### 1.1 Почему не «просто формула» и не «просто нейросеть end-to-end»

| Подход | Точность на практике | Проблема |
|---|---|---|
| Классические формулы (Трухановский, Клювер-Штраух) по ручным промерам рулеткой | ±15–30 кг (3–6%) | Ошибка уже заложена в саму формулу — она не учитывает породу/упитанность без таблиц поправок |
| Те же формулы, но промеры взяты с фото (2D pixel→cm) | ±25–45 кг (5–9%) | Складывается ошибка формулы + ошибка извлечения промеров из 2D-проекции |
| End-to-end CNN «фото → вес» (регрессия без промежуточных признаков) | Нестабильно, сильно зависит от датасета, склонна к переобучению на фон/ракурс/освещение | Не даёт зоотехнической интерпретируемости, требует огромного размеченного датасета взвешиваний конкретной породы/региона, плохо переносится на новую ферму |
| Point Cloud / NeRF полная 3D-реконструкция | Потенциально высокая точность (единичные исследования дают ±1-2%) | На мобильном устройстве требует десятков кадров с движением камеры вокруг животного, животное должно стоять неподвижно 5-15 сек — нереалистично в загоне; тяжело в реальном времени; overkill для прототипа |

**Вывод: ни один из «чистых» подходов не даёт ±10 кг стабильно.** Требуется гибридная
архитектура, которая одновременно устраняет три независимых источника ошибки:

1. **Ошибку масштабирования** (пиксель → см) — решается маркерной калибровкой.
2. **Ошибку измерения промеров** — решается сегментацией + ключевыми точками с
   sub-pixel уточнением, а не одной геометрической эвристикой.
3. **Ошибку формулы** (систематическое смещение классических формул относительно
   реального веса) — решается **обучаемой регрессионной моделью** поверх
   зоотехнических признаков, дообученной на контрольных взвешиваниях (а не
   константными коэффициентами из таблиц 1950-х годов).

### 1.2 Выбранная архитектура: **Keypoints + Segmentation + Marker Calibration + Learned Regression**

```
                    ┌───────────────────────────────┐
                    │   Кадр (CameraX ImageAnalysis) │
                    └───────────────┬─────────────────┘
                                    │
              ┌─────────────────────┼─────────────────────┐
              ▼                     ▼                      ▼
   ┌────────────────────┐ ┌──────────────────┐  ┌────────────────────────┐
   │ ArUco/ChArUco       │ │ Keypoint TFLite  │  │ Depth (ARCore Depth API │
   │ детекция (OpenCV)   │ │ модель (поза)    │  │ / ToF, если есть)       │
   │ → px→cm масштаб     │ │ → 12 landmark'ов │  │ → глубина груди         │
   │ → оценка перекоса   │ │  тела            │  │                         │
   └──────────┬──────────┘ └────────┬──────────┘  └────────────┬────────────┘
              │                     │                           │
              └──────────┬──────────┴─────────────┬─────────────┘
                          ▼                        │
                ┌───────────────────┐              │
                │  Pose Validator    │              │
                │ (боковая проекция, │              │
                │  ракурс, постановка│              │
                │  ног) — reject/pass│              │
                └─────────┬──────────┘              │
                          │ pass                     │
                          ▼                          ▼
                ┌─────────────────────────────────────────┐
                │  BodyMeasurements: пересчёт px → см      │
                │  (косая длина, обхват груди по эллипсу,  │
                │   высота в холке, глубина/ширина груди)  │
                └─────────────────────┬─────────────────────┘
                                      ▼
                ┌─────────────────────────────────────────┐
                │  WeightEstimator                         │
                │  - ML-регрессия (основной путь к ±10 кг) │
                │  - classic formulas (fallback)           │
                └─────────────────────┬─────────────────────┘
                                      ▼
                ┌─────────────────────────────────────────┐
                │  Мульти-кадровая фильтрация:              │
                │  outlier rejection (медиана) + Kalman     │
                └─────────────────────┬─────────────────────┘
                                      ▼
                         Вес (кг) ± доверительный интервал
```

Почему сегментация (YOLOv8-seg) упомянута, но не обязательна в MVP: маска контура
даёт более устойчивую оценку ширины тела при частичном перекрытии ключевых точек
(хвост, конечности), но для MVP её функцию временно выполняет прямое измерение
между ключевыми точками груди (`CHEST_FLOOR` / `CHEST_TOP`). В `BodyMeasurements`
оставлен явный контракт, чтобы заменить это на маску без изменения нижестоящего
кода — см. `morphometry/BodyMeasurements.kt`.

### 1.3 Решение проблемы масштабирования px → см без ошибки перспективы

Два независимых, комплементарных механизма:

1. **Маркерная калибровка (ArUco/ChArUco), а не «фиксированное расстояние».**
   Фиксированное расстояние камера-объект на практике невозможно гарантировать в
   реальном загоне (оператор не может встать ровно в 3.00 м от животного).
   Вместо этого печатный маркер известного физического размера (например, доска
   50×50 см) размещается **в одной плоскости с животным** (на земле рядом,
   перпендикулярно оптической оси камеры). Масштаб px→см вычисляется локально по
   видимому размеру маркера **в конкретном кадре**, поэтому неизвестное и
   переменное расстояние до животного перестаёт быть источником ошибки — оно
   учтено автоматически, т.к. и маркер, и животное отдаляются от камеры одинаково.

2. **Контроль перспективного перекоса.** По соотношению «горизонтальных» и
   «вертикальных» сторон маркера (`ArucoCalibrator.tiltDeg`) оценивается, насколько
   плоскость маркера (≈ плоскость тела животного) отклонена от строгой
   перпендикулярности к оси камеры. Кадры с перекосом > 6° отбраковываются
   `PoseValidator`-ом — это устраняет систематическую ошибку удлинения/укорочения
   промеров, которая иначе была бы главным источником сдвига (bias), а не просто
   шума, и не убиралась бы усреднением по кадрам.

3. **Депth-коррекция там, где есть LiDAR/ToF/ARCore Depth API** (Pixel, часть
   Samsung/iOS-класса устройств): используется как **третий, физически иной**
   источник данных для измерения глубины грудной клетки (переднезаднего размера),
   которую в принципе нельзя получить из одной боковой 2D-проекции. При
   отсутствии сенсора глубины используется эмпирический породный коэффициент
   `depthToWidthRatio` — это осознанный компромисс и явный источник остаточной
   ошибки (см. раздел 4).

### 1.4 Зоотехнические промеры и ключевые точки

Используются классические промеры животноводства (ГОСТ/зоотехнические методики):

- **Косая длина туловища** — от плечелопаточного сочленения (`SHOULDER_JOINT`) до
  седалищного бугра (`ISCHIAL_TUBEROSITY`).
- **Высота в холке** — от холки (`WITHERS`) до земли (`CHEST_FLOOR` как опорная
  точка нижней линии тела в проекции).
- **Обхват груди за лопатками** — не может быть измерен напрямую с одного
  бокового кадра (это периметр эллипса поперечного сечения, а видна только
  ширина). Аппроксимируется периметром эллипса Рамануджана по ширине
  (`bodyWidthCm`, из кадра) и глубине (`bodyDepthCm`, из сенсора глубины или
  породного коэффициента).

## 2. Pipeline обработки кадра

1. **CameraX ImageAnalysis** (`camera/CameraController.kt`) — получение
   `YUV_420_888` буфера, конвертация в `Bitmap`/`Mat`, стратегия
   `STRATEGY_KEEP_ONLY_LATEST` (не копим очередь устаревших кадров, инференс —
   узкое место по времени).
2. **Калибровка масштаба** (`calibration/ArucoCalibrator.kt`) — детекция ArUco
   маркера через OpenCV, вычисление `pixelsPerCm` и оценка перекоса плоскости.
   Если маркер не найден — кадр отбраковывается сразу, без запуска дорогого
   инференса ключевых точек (экономия батареи/времени).
3. **Инференс ключевых точек** (`ml/KeypointDetector.kt`) — TFLite-модель
   (архитектура в духе YOLOv8-pose/MoveNet, дообученная на разметке КРС),
   возвращает 12 анатомических точек с координатами и confidence.
4. **Валидация позы** (`pose/PoseValidator.kt`) — отбраковка кадра, если:
   - не хватает ключевых точек или их confidence ниже порога;
   - рыскание (yaw) больше ±8° (не строго боковая проекция);
   - перекос плоскости маркера/тела > 6° (не перпендикулярно оси камеры);
   - конечности не расставлены раздельно (перекрытие ног искажает промеры).
5. **Извлечение промеров** (`morphometry/BodyMeasurements.kt`) — перевод
   пиксельных расстояний в см через `pixelsPerCm`, расчёт обхвата груди по
   эллиптической аппроксимации.
6. **Расчёт массы по кадру** (`morphometry/WeightEstimator.kt`) — приоритет
   у обучаемой ML-регрессии; классические формулы Трухановского и
   Клювера-Штрауха — как fallback/признаки и как sanity-check (если ML-оценка
   отклоняется от классической формулы более чем на 15%, это сигнал деградации
   входных данных).
7. **Мульти-кадровая фильтрация** (`pipeline/WeightPipeline.kt`) —
   - отбраковка выбросов относительно скользящей медианы принятых кадров;
   - сглаживание фильтром Калмана (`filter/KalmanFilter1D.kt`) по серии из
     10–15 валидных кадров короткого видеофрагмента (~1-2 сек);
   - доверительный интервал сужается пропорционально `1/sqrt(N кадров)`.
8. **Итог**: `WeightResult(weightKg, confidenceIntervalKg, framesUsed, method)`.

### Протокол съёмки (обязателен для достижения ±10 кг)

- Камера на высоте ~1.0–1.2 м, объектив на уровне середины корпуса животного.
- Маркер размещён на земле рядом с животным, в той же плоскости (сбоку от него).
- Животное стоит в «квадратной стойке» — все 4 ноги видны раздельно, голова не
  задрана и не опущена.
- Съёмка серии кадров (видео 1-2 сек) вместо одного фото — устраняет
  единичные ошибки позы/детекции через усреднение и фильтрацию выбросов.
- Рекомендация: съёмка натощак/до утреннего кормления (см. раздел 4).

## 3. Код

Код структурирован как Android-модуль на Kotlin. Ключевые файлы:

- `app/.../camera/CameraController.kt` — настройка CameraX `ImageAnalysis`,
  конвертация YUV → Bitmap.
- `app/.../calibration/ArucoCalibrator.kt` — ArUco-калибровка через OpenCV.
- `app/.../pose/PoseValidator.kt` — валидация ракурса и позы.
- `app/.../ml/KeypointDetector.kt` — инференс TFLite-модели ключевых точек.
- `app/.../morphometry/BodyMeasurements.kt` — px→см промеры, эллиптический
  обхват груди.
- `app/.../morphometry/WeightEstimator.kt` — формулы Трухановского/
  Клювера-Штрауха + ML-регрессия.
- `app/.../filter/KalmanFilter1D.kt` — сглаживание серии оценок.
- `app/.../pipeline/WeightPipeline.kt` — оркестрация полного конвейера.
- `app/.../MainActivity.kt` — UI-обвязка, разрешения камеры.
- `python/train_weight_regressor.py` — референсный скрипт обучения и экспорта
  TFLite-регрессора (запускается отдельно, на стороне сервера/ноутбука, не на
  телефоне).

### Формула зоотехнического пересчёта (реализована в `WeightEstimator.kt`)

**Трухановский:**

```
W(кг) = ОбхватГруди(см)² × КосаяДлина(см) × K / 100
```

где `K` — породно-кондиционный коэффициент (`BreedCondition`, 1.85–2.5:
от худой молочной до упитанной мясной породы). Коэффициент задаётся
пользователем (порода известна на ферме) или оценивается отдельной
классификационной моделью упитанности (Body Condition Score, BCS) по маске
контура — в MVP не реализовано, отмечено как TODO.

**Klüver–Strauch** — полиномиальная аппроксимация табличной поправки
относительно длины тела (упрощение эмпирических таблиц для молочного скота).

**ML-регрессия** (`weight_regressor_fp16.tflite`) — лёгкий MLP (или
градиентный бустинг, конвертированный в TFLite), вход:
`[обхват_груди, косая_длина, высота_в_холке, глубина_груди, ширина_груди, K]`,
выход: скорректированная масса. Обучается на исторических данных «промеры с
фото + контрольное взвешивание на весах» **для конкретной фермы/породы** —
это единственный компонент, который умеет компенсировать систематическое
смещение классических формул и реально приближает точность к ±10 кг.

## 4. Анализ узких мест и погрешностей

### 4.1 Почему ±10 кг критично на практике

Для взрослой коровы 450–700 кг ошибка ±10 кг — это 1.5–2%. При таком уровне
точности данные весов можно использовать для:
- расчёта дозировки ветпрепаратов и кормовых рационов (передозировка/недокорм
  при ошибке >5% ведёт к экономическим потерям и рискам для здоровья животного);
- отслеживания среднесуточного привеса (при типичном привесе 0.8–1.2 кг/сутки
  погрешность взвешивания 20-30 кг делает週недельный тренд не отличимым от шума);
- принятия решений о реализации на убой (цена контракта чувствительна к
  весовой категории).

При погрешности ±20-30 кг (типичной для «формула по фото без калибровки»)
прибор непригоден ни для одной из этих задач — отсюда и жёсткость требования.

### 4.2 Факторы, вносящие наибольшее отклонение

| Фактор | Типичный вклад в ошибку | Митигация |
|---|---|---|
| **Наполненность рубца** (до/после кормления и водопоя) | до ±5–8% живого веса за сутки | Протокол: измерение натощак, утром до кормления; фиксация времени последнего кормления в метаданных |
| **Ракурс/перекос камеры** (yaw/pitch, не строго боковая проекция) | Косинус-ошибка: при отклонении 10° длина/обхват занижаются на ~1.5%, при 20° — на ~6% | `PoseValidator`: жёсткая отбраковка кадров с yaw > 8° и перекосом плоскости > 6°, а не попытка «исправить» ошибку постфактум |
| **Шерстный покров** (зимняя шерсть у мясных пород) | Систематическое завышение обхвата груди на 3-5 см → +1.5-3% к весу | Сезонный поправочный коэффициент по породе/сезону; в перспективе — детекция «пушистости» по текстуре и корректирующий множитель |
| **Стельность (беременность)** | Существенно увеличивает обхват живота без пропорционального увеличения товарной массы, начиная со 2-й половины стельности | Требуется отдельный статус животного как входной метаданные (не определяется по одному боковому фото надёжно) |
| **Порода и упитанность (BCS)** | Определяет коэффициент K в классических формулах; ошибка в породе/BCS = систематическая ошибка 5-15% | Явный выбор породы пользователем + (перспективно) отдельная модель классификации BCS по маске контура |
| **Постановка ног / поза** | Неправильная стойка искажает видимую длину тела и высоту в холке | `PoseValidator.hoovesSeparated()` — отбраковка при перекрытии/сведении ног |
| **Ошибка масштаба (без маркера)** | При допущении «фиксированное расстояние 3 м» и реальном отклонении на 20 см — систематическая ошибка промеров ~6-7% | Маркерная калибровка (раздел 1.3) — не зависит от точного соблюдения дистанции |

### 4.3 Минимизация шума измерений

1. **Съёмка видеофрагмента, а не одного фото** (10-15 кадров за 1-2 сек) —
   даёт независимые (хоть и коррелированные) оценки шума детекции ключевых
   точек.
2. **Отбраковка выбросов по медиане** (`WeightPipeline`) — до сглаживания,
   единичный «плохой» кадр с ошибочной детекцией не тянет среднее.
3. **Фильтр Калмана** (`KalmanFilter1D`) — сглаживание с весом, зависящим от
   `measurementConfidence` (уверенность модели ключевых точек в данном
   кадре) — низкоуверенные кадры вносят меньший вклад в итоговую оценку,
   вместо равного веса при простом усреднении.
4. **Доверительный интервал уменьшается как `1/√N`** — количественно отражает,
   что оценка на 15 валидных кадрах достовернее оценки на 3 кадрах, и это
   значение показывается пользователю, а не скрывается за одним числом.

### 4.4 Честная оценка достижимости ±10 кг

±10 кг **достижимо не как zero-shot свойство алгоритма**, а как результат
всей системы вместе взятой:
- строгий протокол калибровки и позы (устраняет систематические ошибки
  масштаба и ракурса);
- ML-регрессия, **дообученная на контрольных взвешиваниях конкретного стада**
  (устраняет систематическую ошибку формулы/породы);
- мульти-кадровая фильтрация (устраняет случайный шум детекции).

Без дообучения регрессионной модели на локальных данных взвешивания
система будет работать в режиме fallback на классических формулах с
доверительным интервалом около ±25-30 кг — это стоит явно сообщать
пользователю (см. `method` и `confidenceIntervalKg` в `WeightResult`), а не
выдавать псевдоточное число.
